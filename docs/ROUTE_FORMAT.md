# Формат маршрутов (API v1)

Маршрут — это обычный аддон-модуль, который зависит от ядра `FastesBoooy` и
регистрирует данные через глобальную таблицу `FastesBoooy`. Контракт формата
реализован в [`addons/FastesBoooy/Core/Schema.lua`](../addons/FastesBoooy/Core/Schema.lua)
(чистый Lua 5.1, общий для аддона и офлайн-валидатора).

## Структура модуля

```
addons/FastesBoooy_<Name>/
  FastesBoooy_<Name>.toc   -- ## Interface: 16001, ## Dependencies: FastesBoooy
  Route.lua                -- FastesBoooy.RegisterRoute{...}
  Data.lua                 -- (генерируется, make routedata) FastesBoooy.AddRouteData(id, {quests=..., npcs=..., places=...})
  Segments/01_*.lua        -- FastesBoooy.AddSegment(id, {...}) — по файлу на сегмент
```

Файлы грузятся в порядке TOC. `RegisterRoute` должен идти первым.

## Маршрут

```lua
FastesBoooy.RegisterRoute({
    api = 1,                                  -- версия формата (обязательно)
    id = "horde-undead-paladin",              -- [A-Za-z0-9-_]
    title = { ru = "Нежить-паладин 1-22", en = "Undead Paladin 1-22" },
    faction = "Horde",                        -- "Horde" | "Alliance"
    races = { "Scourge" },                    -- raceFile из UnitRace()
    classes = { "PALADIN" },                  -- classFile из UnitClass()
    levels = { 1, 22 },
    version = "1.0.0",
    default = true,                           -- автоматически выбирать для подходящих персонажей
})
```

## Сегмент

```lua
FastesBoooy.AddSegment("horde-undead-paladin", {
    id = "ud-01-deathknell",
    title = { ru = "1-6 Мертвый Звон", en = "1-6 Deathknell" },
    zone = "Tirisfal Glades",
    levels = { 1, 6 },
    steps = { ... },
})
```

## Шаг

Шаг описывает **одно место / одно действие игрока**. В одном шаге можно
совмещать несколько действий (например, сдать и сразу взять квесты у одного NPC) —
шаг завершён, когда выполнены **все** его действия.

### Действия

| Ключ | Значение | Когда шаг считается выполненным |
|---|---|---|
| `accept` | `id` или `{id, id}` | квест(ы) в журнале или уже сданы |
| `turnin` | `id` или `{id, id}` | квест(ы) сданы (`C_QuestLog.IsQuestFlaggedCompleted`) |
| `complete` | `id`, `{id, id}` или `{ [id] = {1, 2} }` | цели квеста (или указанные цели) выполнены, либо квест сдан |
| `abandon` | `id` или `{id}` | квеста нет в журнале |
| `collect` | `{ [itemId] = count }` | в сумках ≥ count |
| `level` | `n` или `{n, доля}` | уровень > n, или = n и доля опыта ≥ доли |
| `go` | `true` | игрок в радиусе `radius` (по умолч. 12 ярдов) от `at` |
| `train` | `true` | окно тренера было открыто и закрыто на этом шаге |
| `fp` | `"Brill"` | открыта карта полётов на этом шаге (точка изучена) |
| `fly` | `"Undercity"` | игрок прилетел (не на такси и в радиусе 60 ярдов от `at`) |
| `sethearth` | `"Brill"` | точка привязки камня изменилась на этом шаге или уже равна месту (имя сравнивается и на языке клиента — через `places` из `Data.lua`) |
| `hearth` | `"Brill"` | игрок в радиусе 80 ярдов от `at` после телепорта |
| `vendor` | `true` | окно торговца было открыто и закрыто |
| `manual` | `true` | только вручную (кнопка «дальше») |

`accept/turnin/complete/abandon/collect/level` — **stateful**: их состояние читается
из игры в любой момент. Остальные — **transient**: наблюдаемы только пока шаг
текущий (или в списке «попутно»).

**Перемотка вперёд.** Если игрок уже ушёл дальше, пропущенные шаги до «границы
перемотки» считаются выполненными — это позволяет подхватить маршрут на уже
прокачанном персонаже и после пустых SavedVariables. Граница = дальнейшее из:

* **опорный шаг** (anchor) — последний не-`bg` шаг с действием `accept`, `turnin` или
  `complete`, у которого выполнены **все** stateful-действия (или отмеченный вручную).
  Доказательством прогресса **не** служат: `level` (уровень можно набрать раньше —
  rested-опыт, гринд, группа — шаг `{ level = 10 }` сам по себе не перематывает более
  ранние `sethearth`/`train`/`fp`; шаг `{ level = 10, accept = Q }` — опорный, когда
  выполнены оба действия), `abandon` (выполнен «пусто» для никогда не взятого квеста),
  `collect` (предметы могут оказаться в сумках случайно), `bg`-шаги;
* сохранённая отметка самого дальнего достигнутого шага (`FastesBoooyCharDB.cursorHint`).

До границы перематываются: transient-действия, шаги `optional` и два «немонотонных»
stateful-действия, которые иначе вернули бы курсор назад: `collect` (предметы обычно
забирает более поздняя сдача квеста) и `accept` квеста, который **более поздний** шаг
маршрута бросает (`abandon`). Остальные stateful-действия (`accept`, `turnin`,
`complete`, `abandon`, `level`) всегда читаются из игры, даже до границы. `bg`-шаги
границей не перематываются, пока игрок в их сегменте (см. `docs/ARCHITECTURE.md`).

**Квест, от которого игрок отказался.** Порядок действий игрока не важен: можно просто
бросить квест в журнале (таймер истёк, элита не по силам, предмет не выпал), нажимать
«Пропустить» не нужно — ни до, ни после. На `QUEST_REMOVED` (кроме `wasReplayQuest`) гайд
через 0,5 с проверяет, что квест не сдан (`QUEST_TURNED_IN` и `QUEST_REMOVED` приходят и
при сдаче) и не вернулся в журнал. Если шаг с `accept` этого квеста уже позади курсора и до
следующего `accept` того же квеста в маршруте нет явного шага `{ abandon = Q }` (тогда
маршрут сам ведёт квест — его поток не меняется), квест считается **оставленным**:

* невыполненные не-`bg` шаги, все действия которых — `complete`/`turnin` этого квеста,
  отмечаются пропущенными (`FastesBoooyCharDB.skipped`; какие отметки поставил гайд —
  в `FastesBoooyCharDB.gaveUp`), в чат пишется «Задание «X» брошено — его шаги пропущены
  (/fb prev — вернуться)»;
* шаг, где квест смешан с другими действиями (`turnin = { Q, R }`, `turnin = Q, accept = R`),
  не отмечается: действия брошенного квеста в нём считаются выполненными, шаг ждёт только
  остальных;
* `accept` квеста остаётся выполненным: курсор не возвращается к нему, автоматика не берёт
  квест снова; шаги после следующего `accept` того же квеста не трогаются;
* квест, взятый заранее (автоматикой через просмотр вперёд) и брошенный до шага с его
  `accept`, ничего не меняет — до `accept` маршрут ещё дойдёт.

Так же оставленным считается квест, более поздний шаг с `complete`/`turnin` которого отмечен
(«Пропустить» / «Дальше») или является `optional`-шагом позади границы перемотки. Вернуть
брошенный квест: взять его снова вручную (отметки гайда снимаются, шаги квеста снова нужны;
если квест взят для следующего `accept` того же квеста в окне автоматики, прежний экземпляр
остаётся пропущенным), `/fb prev` сразу после сообщения (или «Назад» на один из отмеченных
шагов) — курсор вернётся к его `accept`; `/fb reset` забывает и эти отметки. Отметки живут в
SavedVariables, как «Пропустить»: холодный старт с пустыми SavedVariables восстанавливает
курсор по состоянию игры (квеста нет в журнале → его `accept`).

Поэтому в заметках достаточно «бросьте квест», например: «Таймер истёк — бросьте 853 (гайд
сам пропустит шаги)». Явный шаг `{ abandon = Q }` нужен, только когда маршрут сам требует
бросить квест в определённом месте.

### Поля

| Поле | Тип | Назначение |
|---|---|---|
| `id` | string | стабильный id шага (иначе `<segment>:<n>`) |
| `at` | `{uiMapID, x, y}` | точка на карте Forever (x, y в процентах 0–100) |
| `radius` | number | радиус прибытия в ярдах |
| `npc` | id / список | NPC (валидатор проверяет, что он выдаёт/принимает квест и стоит рядом с `at`) |
| `object` | id / список | игровой объект (аналогично) |
| `note` | string или `{ru=, en=}` | подсказка |
| `reward` | `{ [questId] = индекс }` | какую награду выбирать автоматически |
| `gossip` | number | номер опции диалога для автовыбора |
| `use` | itemId | предмет для кнопки «использовать» (`FastesBoooyItemButton`, `/click FastesBoooyItemButton`): видна, пока шаг текущий (или `bg`-шаг в списке «попутно») и предмет в сумках; в бою не меняется до конца боя |
| `bg` | boolean | фоновая цель: не блокирует, висит в списке «попутно», пока не выполнена |
| `optional` | boolean | можно пропустить: считается выполненным, когда он позади границы перемотки (выполнен более поздний опорный шаг `accept`/`turnin`/`complete`, не просто `level`) |
| `class` / `race` / `faction` | токен или список | фильтр: шаг показывается только подходящим персонажам |
| `spells` | список строк | что выучить у тренера (только отображение) |

### Пример

```lua
steps = {
    { accept = 363, npc = 1568, at = { 1420, 30.2, 71.7 } },
    { turnin = 363, accept = 364, npc = 1569, at = { 1420, 30.8, 66.2 } },
    { complete = 364, bg = true, note = { ru = "Бейте зомби по пути", en = "Kill zombies on the way" } },
    { level = { 4, 0.3 } },
    { train = true, class = "PALADIN", npc = 12345, at = { 1420, 31.1, 66.0 } },
    { go = true, at = { 1420, 59.4, 52.1 }, note = { ru = "Бегите в Брилл", en = "Run to Brill" } },
}
```

## Валидация

`make validate` (см. `tools/validate_routes.lua`) проверяет каждый маршрут по
снимку базы Forever (`tools/data/forever_db.lua`): существование квестов,
доступность для расы/класса/фракции, требования по уровню (симуляция опыта),
цепочки (pre-quests, exclusive), принадлежность NPC и расстояние от `at` до
спавна, ёмкость журнала, тренеров/полётчиков/трактирщиков. Подробнее —
[VALIDATION.md](VALIDATION.md).
