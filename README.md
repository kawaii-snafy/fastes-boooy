# Fastes Boooy — модульный гайд быстрой прокачки для World of Warcraft: Forever

Аддон-гайд для **World of Warcraft: Forever** (клиент 1.60.1, `## Interface: 16001`).
Ядро ведёт по маршруту шаг за шагом: показывает текущий шаг и стрелку к цели,
само берёт и сдаёт квесты маршрута, само отслеживает прогресс. Маршруты подключаются
отдельными аддонами-модулями.

| Аддон | Что это |
|---|---|
| `FastesBoooy` | ядро: движок маршрутов, автоматизация квестов, стрелка, окно шагов, настройки |
| `FastesBoooy_Horde` | общий путь Орды 22–60 (библиотека сегментов без классовых шагов); нужен модулям маршрутов, сам по себе не гайд |
| `FastesBoooy_UndeadPaladin` | маршрут **Нежить-паладин (Орда) 1–60** |
| `FastesBoooy_SkyborneDruid` | маршрут **Скайборн-друид (Орда, Windshaper) 1–60** |

Маршрут выбирается автоматически по расе, классу и фракции персонажа.
До 22-го уровня у каждого маршрута свой путь, с 22-го — общий путь Орды из `FastesBoooy_Horde`
с классовыми вставками (тренер, классовые квесты, верховая езда на 40-м).

## Установка

1. Скопируйте папки из `addons/` в `World of Warcraft/_forever_/Interface/AddOns/`
   (Battle.net → шестерёнка → «Показать в проводнике» → `_forever_`; у беты папка была `_classic_beta_`).
   Нужны **все три части**: ядро `FastesBoooy`, общий путь Орды `FastesBoooy_Horde` и модуль(и)
   маршрутов. Модули маршрутов объявляют `## Dependencies: FastesBoooy, FastesBoooy_Horde`:
   без `FastesBoooy_Horde` клиент их не загрузит, и гайда не будет вовсе (даже 1–22).
   Ядро должно быть той же или более новой версии, что и модули (модулям 1–60 нужно ядро 0.2.0+).
   Готовые zip-архивы собирает `make package` (в `dist/`, по архиву на каждую папку — нужны
   `FastesBoooy-*.zip`, `FastesBoooy_Horde-*.zip` и архивы маршрутов).
2. На экране выбора персонажа включите аддоны («AddOns»).
3. В игре: окно гайда появится автоматически. `/fb` выводит список команд.

## Команды

| Команда | Действие |
|---|---|
| `/fb show` / `/fb hide` | показать / скрыть гайд |
| `/fb lock` / `/fb unlock` | закрепить / открепить окна |
| `/fb next` / `/fb prev` / `/fb skip` | вперёд / назад / пропустить шаг |
| `/fb routes`, `/fb route <id>` | список маршрутов / выбрать маршрут |
| `/fb reset` | сбросить прогресс персонажа |
| `/fb config` | настройки (также в меню «Настройки → AddOns») |
| `/fb delay [сек [добавка]]` | пауза автоматики перед каждым действием: `/fb delay` — показать, `/fb delay 1 0.5` — 1 с + случайно до 0,5 с, `/fb delay 0` — мгновенно |
| `/fb status` | текущее состояние |
| `/fb xp [chat\|clear]` | записанный в игре опыт за квесты (см. «Ограничения») |

Если у шага есть предмет, который нужно использовать, рядом с окном гайда появляется **кнопка
предмета** (клик — использовать; перетаскивание — правой кнопкой). На клавишу её можно назначить
макросом `/click FastesBoooyItemButton`.

Если решили отказаться от квеста (истёк таймер, элита не по силам, не выпал предмет), просто
бросьте его в журнале — нажимать «Пропустить» не нужно, порядок не важен. Гайд сам пропустит
оставшиеся шаги этого квеста, не вернётся к шагу, где его берут, и напишет об этом в чат.
Передумали — `/fb prev` сразу после сообщения или снова возьмите квест: его шаги вернутся.

Если зажать **Shift** при открытии диалога с NPC, автоматика на этот диалог отключится.
Автоматически аддон берёт только квесты из ближайших шагов маршрута, а сдаёт
только квесты, которые есть в маршруте. Если наград несколько и в маршруте не указано,
какую брать, выбор остаётся за вами.

Автоматика действует не мгновенно, а с небольшой «человеческой» паузой: по умолчанию
0,5 с + случайно до 0,3 с перед каждым принятием, сдачей, выбором награды или реплики
(настройки «Задержка автоматики» и «Случайная добавка», 0–3 с и 0–1 с, или `/fb delay`;
0 — мгновенно, как в других аддонах). Пока идёт пауза, окно можно закрыть или нажать
**Shift** — действие отменится (Shift — до конца диалога с этим NPC); если за это время
окно сменилось, аддон ничего не делает.

## Как устроено

* [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) — устройство ядра и движка.
* [docs/ROUTE_FORMAT.md](docs/ROUTE_FORMAT.md) — формат маршрутов (API v1): как написать свой модуль.
* [docs/routes/](docs/routes/) — описания маршрутов: хабы, уровни, план обучения, таланты.
* [docs/VALIDATION.md](docs/VALIDATION.md) — отчёт валидатора по маршрутам (генерируется `make report`)
  и список того, что подтверждается только в игре.
* [tools/README.md](tools/README.md) — офлайн-инструменты.

Прогресс восстанавливается по состоянию игры: сданные квесты, журнал квестов и уровень.
Поэтому гайд сам находит нужный шаг, даже если сохранённые данные потерялись
(на ранних билдах Forever такое случалось после холодного перезапуска клиента).

## Проверка без игры

```sh
sudo apt-get install lua5.1 lua-check lua-busted   # или luarocks: luacheck, busted
make check      # lint + test + validate + simulate
```

| Цель | Что проверяет |
|---|---|
| `make lint` | luacheck со стандартом `forever`. Он собран из полного списка API клиента Forever (`tools/data/forever_api.lua`), поэтому вызов несуществующей в Forever функции, поля `C_*` или `Enum` — ошибка |
| `make test` | busted-спеки ядра, валидатора и строгого мока клиента. Мок разрешает только функции, события, шаблоны и методы виджетов, которые реально есть в Forever |
| `make validate` | валидатор маршрутов по снимку БД Forever (`tools/data/forever_db.lua`). Проверяет: квест существует в Forever и доступен расе, классу и фракции; уровень (по симуляции опыта); цепочки и взаимоисключения; кто выдаёт и принимает квест; расстояние от точки до NPC; тренеров, полётчиков и трактирщиков; журнал на 40 квестов; квесты профессий в обязательных шагах; шаг `complete` у триггера области; визиты к тренеру/торговцу, которые перемотает автопринятие квеста того же NPC |
| `make simulate` | прогон каждого маршрута через настоящий движок на моке: каждый шаг должен завершаться ровно тем действием, которое он требует, включая автопринятие и автосдачу |
| `make report` | перегенерировать `docs/VALIDATION.md` |

CI (`.github/workflows/ci.yml`) запускает `make check` на каждый push и проверяет, что `Data.lua` модулей
и `docs/VALIDATION.md` актуальны (после изменения маршрутов: `make routedata` и `make report`).

## Чем Forever отличается от Classic (и почему понадобилась валидация)

* Современный API (`C_QuestLog`, `C_GossipInfo`, `C_Map`, `C_Item`, …): многих функций Classic
  (`GetQuestLogTitle`, `GetItemCount`, `IsQuestFlaggedCompleted`, …) в клиенте нет.
* Новая раса Скайборн (raceFile `Skyborne`, у Орды raceID 96) со стартовой зоной Zephras Isle
  (uiMap 2521) и отплытием в Mulgore. Новая комбинация Нежить-паладин со своей цепочкой классовых
  квестов и тренерами (Deathknell, Brill, Bandarion Keep, Undercity, Thunder Bluff).
* Около 750 новых квестов, изменённые уровни. Геометрия карты Mulgore изменена:
  координаты из Classic там неверны. Журнал квестов на 40. Cat Form друида — через цепочку в Moonglade.
* Таблица опыта по уровням и штраф за «серые» квесты — как в Classic. Зелёные мобы дают меньше опыта.

## Ограничения (честно)

* **Аддон не запускался в живом клиенте Forever.** Проверено всё, что можно проверить офлайн:
  статический анализ по списку API билда Forever, тесты на строгом моке клиента, валидация
  маршрутов по базе Forever и симуляция прохождения.
  Что подтверждается только в игре, перечислено в конце [docs/VALIDATION.md](docs/VALIDATION.md)
  (раздел «Что подтверждается только в игре»). Например, срабатывает ли автопринятие квестов
  без аппаратного события и использует ли предмет защищённая кнопка `FastesBoooyItemButton`.
* **Опыт за новые квесты Forever офлайн неизвестен**: ни в одном доступном источнике его нет.
  Валидатор его оценивает, а аддон записывает реальный опыт при сдаче квеста.
  Команда `/fb xp` выводит эти данные, по ним можно уточнить маршруты.
* Данные БД — снимок на 2026-11-07, билд 1.60.1.70862.
