# Поправки к снимку БД (`tools/overrides`)

Снимок `tools/data/forever_db.lua` собирается из внешних данных (`make db`) и местами расходится с игрой:
опыт нового квеста неизвестен, в маске рас не хватает расы, пара квестов записана взаимоисключающей.
Поправка к одному квесту или NPC кладётся сюда, а не в снимок: она переживает `make db`, у неё есть
источник и отметка «проверено в игре».

Читает их `DB.ApplyOverrides` (`tools/lib/fbdb.lua`). Три инструмента (`validate_routes.lua`,
`simulate_routes.lua`, `gen_route_data.lua`) применяют поправки по умолчанию; `--no-overrides` отключает
их, `--overrides DIR` берёт другой каталог. `DB.Load` сам ничего не применяет, а цели make для фикстур и
все тесты, которые запускают инструменты на фикстурах, передают `--no-overrides`: числа в тестах не
зависят от этого каталога (за этим следит `tests/spec/validator_overrides_spec.lua`).

## Формат файла

Один файл на владельца: `tools/overrides/<имя>.lua`. Файл — одно выражение `return { ... }`, он
выполняется в пустом окружении (никаких глобальных имён; `luacheck` проверяет это правилом
`files["tools/overrides/*.lua"]`).

```lua
return {
    quests = {
        -- опыт квеста (используется без предупреждений)
        [92461] = { xp = 85, source = "in game 2026-11-12", verified = true },
        -- квест доступен ещё одной расе / классу
        [4641] = { races = { add = { "Troll" } }, source = "https://www.wowhead.com/...", verified = false },
        [2383] = { classes = { add = { "WARRIOR" } }, source = "in game 2026-11-12", verified = true },
        -- списки квестов: add и / или remove
        [861] = { exclusive = { remove = { 844 } }, source = "in game 2026-11-12", verified = false },
        [860] = { preSingle = { add = { 861 } }, preGroup = { remove = { 870 } }, source = "...", verified = false },
        -- «проходной» квест: id целевого квеста или false
        [854] = { breadcrumbFor = false, source = "in game 2026-11-12", verified = true },
    },
    npcs = {
        [3153] = { sub = "Warrior Trainer", source = "in game 2026-11-12", verified = true },
    },
}
```

| Поле квеста | Значение |
|---|---|
| `xp` | число больше нуля: базовый опыт квеста |
| `races`, `classes` | `{ add = { ... } }`: raceFile (`"Scourge"`, `"Troll"`, `"Skyborne"`) или токен класса. Маска «для всех» (0) не меняется |
| `exclusive`, `preSingle`, `preGroup` | `{ add = { id, ... }, remove = { id, ... } }`, достаточно одного из двух. `exclusive.remove` убирает пару в обе стороны |
| `breadcrumbFor` | id квеста или `false` |
| `source` | обязательно: ссылка или `"in game ГГГГ-ММ-ДД"` |
| `verified` | `true`, когда значение проверено в клиенте Forever; по умолчанию `false` |

У NPC меняется только `sub` (подпись под именем: по ней валидатор узнаёт тренера класса). Квесту вне
снимка (есть только в `questIndex`, валидатор пишет `quest-out-of-scope`) можно задать `xp`, `races` и
`classes`.

## Правила

* **Порядок.** Сначала `DB.Prepare` считает медианы опыта по уровню квеста — по снимку. Потом
  применяются поправки. Поэтому `xp` одного квеста никогда не сдвигает оценку опыта другого.
* **Сломанный файл не останавливает остальных.** Файлы читаются в постоянном порядке: сначала
  `shared.lua`, потом остальные по алфавиту, каждый под `pcall`. Файл, который не загрузился или записан
  с ошибкой формата, пропускается целиком, и о нём печатается одна строка: `ERROR override-load` при
  полном запуске, заметка (`note`) при запуске с `--skip`.
* **Один id — один файл.** Квест или NPC может стоять только в одном файле; ошибочным считается файл,
  прочитанный позже. `shared.lua` читается первым, поэтому файл владельца, который повторил id из
  `shared.lua`, пропускается сам и не выключает общий файл для остальных.
* **Владелец.** Файл `<имя>.lua` относится к тем файлам модуля, у которых имя файла (без `.lua`) или
  каталог совпадает с `<имя>` без учёта регистра: `warrior.lua` → `Classes/Warrior.lua`,
  `durotar.lua` → `Segments/Durotar/*`, `orc.lua` → `Races/Orc.lua`. `shared.lua` относится ко всем.
  `ERROR override-foreign-quest`: поправка не из `shared.lua` называет квест, который использует
  загруженный шаг вне файлов владельца. Значение для квеста общего пути идёт в `shared.lua`; его правят
  только фазы с одним владельцем, остальные сообщают значение в записке о передаче.
* **Непроверенная поправка видна в отчёте.** Шаг, который проходит проверку (раса, класс,
  взаимоисключение, предусловие, тренер) только благодаря поправке с `verified = false`, получает
  `WARN db-override-unverified`. Его либо снимают, проверив в игре (`verified = true`), либо принимают:
  `ok = "db-override-unverified"` на шаге и комментарий `-- CONFIRM: ...` в той же строке. Поправки `xp`
  используются молча.

## Проверка своего файла

```
luacheck --config .luacheckrc tools/overrides/<имя>.lua
lua5.1 tools/validate_routes.lua -q --route <маршрут>
```

Валидатор печатает строку `validate_routes: DB overrides from tools/overrides: N file(s) (...)`, когда
в каталоге есть файлы.
